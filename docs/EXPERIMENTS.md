## 成功率与平均得分应分开

[WebShop 原论文第 3.1 节](https://arxiv.org/abs/2207.01206) 将两项指标分开报告：

- 任务得分：平均奖励乘以 100。
- 成功率：终局奖励等于 1 的任务所占比例。

笔记采用“奖励超过 0.5”判断成功，会计入一部分未完全满足条件的任务。若该阈值用于实际评测，应将结果命名为“奖励超过 0.5 的任务比例”，同时另报标准成功率，不能与论文成功率直接比较。

原论文、实现和日志可能使用不同的奖励显示尺度；例如 0–1 与 0–100。复核时需要检查转换方式、边界条件以及失败任务是否计入分母。

## 原论文结果，仅作背景

[SPA-RL 原论文第 7 页图 2](https://arxiv.org/abs/2505.20732v1) 报告的 WebShop 成功率为：

| 原论文方法 | 成功率 |
| --- | ---: |
| 监督微调 | 62.0% |
| PPO | 62.1% |
| RAGEN | 63.0% |
| SPA-RL | 64.1% |

这些是原作者的实验结果，不是本仓库的复现结果。论文附录表 6 列出的 WebShop 训练／测试规模为 1,938／200；项目笔记写的是约 1,600 条轨迹与 100 条测试指令，两种计数单位和划分不能直接等同。评测集合与成功判定均未对齐，不能从笔记中的更高百分比推断超越原论文。

## 将记录转为可验证结果所需材料

1. 代码仓库与提交编号、依赖环境、精确模型名称和模型版本。
2. 训练配置、数据来源、训练／验证／测试任务列表、随机种子及去重方式。
3. 监督微调和 PPO 的训练日志、检查点标识及实际奖励实现。
4. 每个测试任务的动作轨迹、最终奖励、是否成功、失败原因和截断状态。
5. 能从逐任务记录重新计算平均得分与标准成功率的评测脚本。

待这些材料补齐后，再解决 84%／86% 与数据划分冲突，记录复核日期，并更新首页结论。本次整理没有运行训练或生成新的性能数值。
